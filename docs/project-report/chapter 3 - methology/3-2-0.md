# Functional Requirements:

- The system shall provide a user-friendly interface for inputting land dimensions and general requirements.
- The system shall support land geometry entry through convex polygon coordinates or simple dimension forms.
- Users shall be able to provide a room list including room type, count, and approximate size or minimum/maximum dimensions.
- The system shall automatically calculate the maximum buildable footprint and available area based on Sri Lankan setback and zoning regulations.
- The system shall generate multiple candidate 2D floor plan layouts that satisfy both user requirements and residential housing regulations.
- The Floor Plan Generation Algorithm shall include the placement of windows and doors in appropriate locations according to rules and best practices.
- The system shall include an intuitive Constraint Modification Interface to allow users to adjust non-fixed regulatory parameters.
- The system shall display appropriate warnings when user-adjusted constraints affect regulatory compliance.
- The system shall provide a pre-validation step to inform users if their requested requirements are mathematically impossible for the given land.
- The system shall allow users to export or download floor plan sketches (SVG/PNG) and raw coordinates.
- The system shall support switching between different municipal regulation profiles or rule sets via configuration files or an admin UI.
- The backend shall utilize a constraint-based solver engine (Google OR-Tools CP-SAT) for generation.

Non-Functional Requirements:

- Performance: A single floor plan generation operation shall complete within 60 seconds under normal conditions (90% of requests).
- Usability: The interface shall be simple enough for non-technical users to complete a baseline input flow within 5 minutes without external help.
- Responsiveness: The web application must be responsive and functional across various devices.
- Real-time Feedback: The system is designed to provide near-instant feedback and real-time visualization of the algorithm's dynamic operation.
- Correctness: Generated plans must strictly adhere to hard regulatory constraints such as setbacks, coverage limits, and minimum room sizes.
- Practicality: Layouts shall consider practical design aspects including walking distances, plumbing routes, airflow, and spatial connectivity (e.g., corridors/hallways).
- Aesthetics: The system aims to produce well-balanced and aesthetically pleasing floor plan layouts.
- Robustness: The system shall gracefully handle invalid inputs and report clear, actionable errors.
- Extensibility: The codebase shall follow a modular Object-Oriented Programming (OOP) structure, allowing for new regulation profiles or constraint modules to be added with minimal code changes.
- Maintainability: The system shall include unit and integration tests for core constraint logic to ensure reliability.
- Interactive Visualization: The application will feature a canvas-like interface for interactive visualization and adjustment of land dimensions.
